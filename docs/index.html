Measurements, actions & limits

CPU averages, peaks, and short bursts

The first reading is discarded because it has no prior interval. Averages use observed intervals; peaks show the highest interval, not an instantaneous maximum. The overall CPU card measures all logical cores on a 0–100% scale. Each process uses 100% for one core. A short burst can be useful work. A process seen only once may have no usable CPU reading.

Memory footprint, RSS, and memory growth

Footprint is macOS’s physical footprint, including compressed allocations. Resident memory (RSS) is a different reading from ps, collected just after the sample; it excludes compressed allocations and can count shared pages. App totals combine helpers and are approximate. In-sample group trends cover helpers still present in the final reading; exited helpers are outside these curves. Within-sample changes can reflect a changing set of helpers; changes between scans compare groups by executable/app path and user. Growth across a short sample does not prove a leak. Use memory pressure and active swap transfers for context.

Power, sleep assertions, network, and disk

Power proxy is top’s POWER score: CPU activity plus idle wakeups. It is not watts or Activity Monitor Energy Impact and does not include GPU, disk, or networking energy. Kernel wakeups remain visible for context but do not drive review priority. Sleep assertions can be normal during calls, playback, backups, or an active display. Network rates cover en interfaces and exclude loopback, VPN, and peer-to-peer interfaces to reduce duplicate accounting. Disk counters are rounded iostat counters, with reads and writes combined. Exposed devices can include disk images. These rates are system/device measurements, not per-process I/O.

How priority works

The score is the highest of average CPU, footprint, power, and wakeups divided by twice their configured review threshold. Add 0.25 for an idle-system-sleep blocker, and 0.50 if memory pressure is elevated and footprint crosses the memory threshold. A score of 1 or more is High. Other threshold crossings or CPU bursts are Review. These are investigation hints. Custom thresholds are browser preferences; the saved snapshot retains default analysis.

History, privacy, and scan controls

The script keeps the latest 40 group-level scans by default, in Mac Resource History.json beside the dashboard. --history changes the limit to 1–120. History belongs to this report folder and is checked against RAM, CPU count, and user ID; avoid mixing reports from different Macs. Process comparisons use paths and users, not PIDs, because PIDs can be reused. Pins track owning apps; all same-app helpers may share a pin in process view. A browser cannot start a native scanner from this offline file: use the supplied launcher or copy a command from Scan options. Refreshing the page alone does not collect data. Watch mode refreshes the page without resetting your view, with pause controls and a visible scan age. No information is uploaded; raw network addresses are omitted from exports. Process paths and assertion descriptions are included, so review reports before sharing.
